# Локальный стенд роли

Запускать на RED OS 7.3 с уже работающим MinIO и настроенным административным
alias `lab` у пользователя, выполняющего команды. Сервер доступен по `http://127.0.0.1:9000`.
В `group_vars/minio_cluster/minio-config.yml` укажите фактический путь к MinIO Client
(`/usr/bin/minio-client`). Административный пароль роль не использует: он хранится в alias.

Inventory использует локальное подключение, playbook — `become: false`.
Каталог политик для apply должен быть подготовлен с учётом владельца, заданного ролью.
Пароли тестовых пользователей открыто заданы в group_vars для этого стенда.

Команды из корня проекта:

```bash
export ANSIBLE_ROLES_PATH="$PWD/roles"

# Проверить синтаксис.
ansible-playbook -i lab/inventory.yml lab/playbook.yml --syntax-check

# Посмотреть план изменений.
ansible-playbook -i lab/inventory.yml lab/playbook.yml -e minio_configuration_mode=dry

# Создать тестовую конфигурацию.
ansible-playbook -i lab/inventory.yml lab/playbook.yml

# Построить матрицу текущего состояния.
ansible-playbook -i lab/inventory.yml lab/playbook.yml -e minio_configuration_mode=matrix

# Выгрузить текущую конфигурацию в YAML.
ansible-playbook -i lab/inventory.yml lab/playbook.yml -e minio_configuration_mode=export
```

Отчёты сохраняются в каталоге `lab/`. Штатный `--check` можно добавить к любому
запуску; он не заменяет режим `dry` и не записывает файлы отчётов.
Существующие пользователи вне inventory сохраняются, бакеты не удаляются.
Группы не создаются. Роль не загружает объекты: матрица строится по политикам.

Ожидаемые значения для тестовых пользователей:

| Ресурс | `u:lab-prefix-writer` | `u:lab-reader` | `u:lab-delete-only` | `u:lab-test` | `anonymous` |
|---|---|---|---|---|---|
| `lab-data/*` | `L  R  -  -` | `-  -  -  -` | `-  -  -  D` | `-  -  -  -` | `-  -  -  -` |
| `lab-data/reports/*` | `l  R  W  D` | `-  -  -  -` | `-  -  -  d` | `-  -  -  -` | `-  -  -  -` |
| `lab-other/*` | `-  -  -  -` | `L  R  -  -` | `-  -  -  -` | `-  R  -  -` | `-  -  -  -` |
| `lab-other/other/*` | `-  -  -  -` | `l  r  -  -` | `-  -  -  -` | `L  R  W  D` | `-  -  -  -` |
| `lab-public/*` | `-  -  -  -` | `-  -  -  -` | `-  -  -  -` | `-  -  -  -` | `-  R  -  -` |

На общей строке lab-data у lab-prefix-writer показано `L  R  -  -`.
Запись и удаление разрешены только в `reports/*` и показаны на строке этого префикса,
без дополнительных обозначений на общей строке.
`s3:*` относится к объектному ARN префикса; `L` обеспечивается отдельным правилом
ListData на ARN бакета. Действия за пределами L/R/W/D отмечаются в пояснениях.

Заглавные L/R/W/D — правила самой строки, строчные l/r/w/d — права из более
широкой области. У lab-reader на `lab-other/*` показано `L  R  -  -`,
на `lab-other/other/*` — `l  r  -  -`. Отдельное правило на префикс сохраняет
заглавную букву, даже если аналогичное разрешение есть выше.

`?` без буквы действия означает неизвестный результат в соответствующей позиции
L/R/W/D: например, `-  ?  -  -` — неизвестно R.
Права и запреты вложенных областей не суммируются на родительских строках;
для конкретного объекта учитывайте соответствующую более узкую строку.

Для lab-test список разрешён через `Condition: StringLike: s3:prefix: ['other/*']`.
Общая строка `lab-other/*` не получает L от этого правила;
строка `lab-other/other/*` получает L. Правила IP/TLS/времени матрица пока не вычисляет.

## Проверка реальных прав через minio-client

После применения inventory запустите из корня проекта:

```bash
./lab/check-access.sh
```

Скрипт использует именно установленный `minio-client` из PATH. Административный
alias — `lab`, endpoint — `http://127.0.0.1:9000`, тестовый пользователь — `lab-test`,
пароль — `Test-Only-123` из inventory. Для другого alias/endpoint или изменённого
пароля задайте `MINIO_LAB_ADMIN_ALIAS`, `MINIO_LAB_ENDPOINT`, `MINIO_LAB_TEST_PASSWORD`.
Endpoint должен указывать на тот же сервер, что и административный alias.

Команды в скрипте проверяют:

- список `other/` и вложенного префикса;
- чтение по заранее известному имени внутри и вне `other/`;
- создание, перезапись, чтение и удаление внутри `other/`;
- отказ в списке всего бакета и постороннего префикса;
- отказ в создании, перезаписи и удалении вне `other/`;
- сохранность исходного содержимого после запрещённых операций.

Проверки выполняются от тестового пользователя через временный alias и отдельный
каталог конфигурации клиента. Существующий alias `lab` не меняется. Администратор
создаёт исходные объекты и удаляет только объекты с уникальными именами текущего
запуска, включая очистку при ошибке. Бакеты, политики и пользователи скрипт не удаляет.
Ожидаемый отказ принимается только при сообщении AccessDenied/Access Denied или
Insufficient permissions; ошибки соединения и другие сбои приводят к FAIL.

Это проверка базовых L/R/W/D, не полный тест всех операций S3 и versioning.
Вывод успешного запуска содержит восемь строк PASS и итоговое сообщение.

Для независимой проверки с нуля доступен
`python3 roles/minio-configuration/tests/live_prefix.py`: он запускает отдельный
временный сервер на случайных локальных портах, применяет политики lab-test,
запускает тот же check-access.sh и проверяет матрицу по реальному JSON. Нужны
`/usr/bin/minio`, `minio-client`, Python с Ansible и PyYAML. Данные и конфигурация
создаются в `.ansible/` и удаляются при завершении; существующий стенд не используется.
