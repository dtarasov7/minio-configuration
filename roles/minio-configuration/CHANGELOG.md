# Изменения

## 3.5.0 — 2026-10-16

- Dry выводит сводку добавлений, изменений и удалений в кластере; чтения и подготовка локальных каталогов/файлов исключены из плана.
- План сравнивает наличие бакетов, versioning, статусы, JSON-политики и назначения с текущим состоянием; различает создание и изменение политик, включает создание групп.
- Добавлена переменная `minio_configuration_dry_report_path` для YAML-отчёта на Ansible-контроллере с правами `0600`; пустая строка отключает сохранение, `--check` сохраняет штатное поведение без записи файла.
- Пароли скрываются; явно заданная смена ключа и применение публичных anonymous-пресетов отражаются как запланированные операции.
- Обновлены README на двух языках и проверки сравнения состояния, сводки, фильтрации тегами и сохранения отчёта.

## 3.4.0 — 2026-10-16

- Полностью удалён этап `clean`: файл задач, импорт и теги `clean`/`never`, удаление объявленных пользователей и созданных файлов политик при очистке.
- Удалены операции очистки из dry-плана; сохранено удаление отсутствующих в inventory пользователей по явному флагу `minio_configuration_users_delete` с защитой служебных учётных записей.
- Обновлены тесты, оба README и документация заявок. История изменений сохранена.

## 3.3.0 — 2026-10-16

- Полностью исключено удаление бакетов: как отсутствующих в inventory, так и объявленных при `clean`; пустые и непустые бакеты и их содержимое сохраняются.
- Удалены переменная `minio_configuration_backets_delete`, её производные и операции удаления бакетов из dry-плана.
- `clean` удаляет только объявленных незащищённых пользователей и созданные файлы политик на delegate-хосте.
- Обновлены README, каталог заявок и проверки; Molecule проверяет сохранение пустого бакета и данных в непустом бакете, отсутствующих в inventory.

## 3.2.0 — 2026-10-16

- Поведение роли задаётся переменной `minio_configuration_mode`: `apply` (по умолчанию), `dry` или `export`; значение можно определить в inventory или через `-e`.
- Удалены теги выбора режима `dry`, `dryrun` и `export`, а также вычисление промежуточной переменной режима по тегам.
- Теги этапов фильтруют задачи применения и соответствующие части плана; режим экспорта выполняет только проверки доступа и выгрузку.
- Штатный `--check` Ansible независим от режима роли. Запросы чтения выполняются, изменяющие команды учитывают check mode; экспорт с `--check` не записывает файл.
- Добавлена проверка допустимых значений режима; обновлены локальные тесты и Molecule-сценарий.
- Восстановлена полная история изменений на русском и английском языках. README описывают только текущий интерфейс роли.

## 3.1.0 — 2026-10-16

- Добавлены пустые строки перед каждой задачей в роли, примерах, локальных тестах и Molecule, включая вложенные block/rescue/always.

## 3.0.0 — 2026-10-16

- Зафиксирован читаемый порядок полей политик; списки Action/NotAction и Resource/NotResource экспортируются в одну строку с корректным YAML-экранированием.
- Экспорт содержит только три списка переменных (users, groups, backets) без обёртки inventory и служебных параметров; у каждой сущности первым идёт name, у бакетов далее anonymous/anonymous_policy и versioning.
- Удалена публичная переменная `minio_configuration_mode`; действия выбираются тегами, просмотр поддерживает `--check`.
- При наличии старой переменной роль останавливается с инструкцией по переходу.
- Предварительные проверки наследуют только `always`; убраны тег `pre-req` и повторные теги статических задач.
- Экспорт помечен `never`/`export`, запускается явно и не записывает переменную режима в inventory.
- Краткие способы запуска перенесены в начало обоих README; подробности оставлены в соответствующих разделах.
- Обновлены локальные проверки и Molecule для запуска экспорта/dryrun через CLI-теги.

## 2.0.0 — 2026-10-15

- Роль использует установленный `mc` и существующий alias; `admin info` проверяет доступ и останавливает запуск при ошибке.
- Удалены настройка alias, административные учётные данные и переменные подключения/скачивания клиента.
- `minio_configuration_mc_binary_path` задаёт полный путь с именем бинарника (`mc` или `mcli`).
- Добавлен `dryrun`: чтение состояния, план операций без изменений, скрытие паролей, поддержка тегов и `--check`.
- `install` создаёт только каталог политик; подготовка выполняется и с тегами `user`/`backet`, если нужны файлы политик.
- Экспорт больше не содержит endpoint и учётные данные администратора.
- Добавлены проверки dryrun и остановки при отсутствии alias/бинарника; обновлена подготовка Molecule.

- Исправлены теги предварительных проверок, подключения и вложенных задач.
- `--tags export` включает экспорт без изменения объектов MinIO, в том числе при сочетании тегов.
- В экспорт добавлен справочный снимок всех исходных IAM-политик, включая неназначенные.
- Добавлены проверки запуска роли с тегами `export` и `user`.

## 1.0.0 — 2026-10-08

- Добавлены стандартные режимы и явные IAM-политики анонимного доступа.
- Добавлены несколько IAM Statement и именованных политик для пользователя,
  явные запреты, маски бакетов и объектов, условия доступа.
- Пользователи обновляются без удаления; пароль можно опустить для существующего пользователя.
- Добавлен экспорт inventory YAML с бакетами, политиками, пользователями и группами.
- Удалена поддержка переменных без префикса `minio_configuration_`.
- Добавлены локальные проверки и сценарии Molecule для прав доступа и экспорта.

- Defaults переведены на явные IAM Statement без изменения стандартных разрешений.
- Членство пользователя задаётся полем groups и синхронизируется во всех текущих группах;
  отсутствие поля снимает всё членство. Группы создаются по назначенным пользователям.
- Alias mc задаётся переменной minio_configuration_alias и сохраняется в экспорте.
- В README добавлены 59 имён S3 Action релиза 2025-10-15 и s3:*, ограничения API,
  примеры NotResource и явных исключений Deny.

- Удалена сокращённая форма пользовательских разрешений; права задаются IAM Statement.
- Группы поддерживают statements прямо в описании, как пользователи.
- Сгенерированные политики разделены по сущностям: minio-configuration-user-<имя>
  и minio-configuration-group-<имя>. Одинаковые прямые права разных пользователей
  создают отдельные политики; права группы наследуются всеми её участниками.

- Каждое правило пользователя и группы создаёт отдельную политику с именем владельца,
  Sid и типом user/grp. Совместное назначение создаваемых ролью политик запрещено.
- Sid обязателен и уникален внутри одного владельца; у разных владельцев может совпадать.
- Перед изменением документов проверяются прямые назначения всем внутренним пользователям
  и группам, включая созданных вне роли; чужое назначение блокирует изменение.
- Удалены общие списки политик. Экспорт разворачивает текущие политики в statements
  владельцев и формирует устойчивые Sid для отсутствующих/повторяющихся идентификаторов.
