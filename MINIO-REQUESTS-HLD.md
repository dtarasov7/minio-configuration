# Заявки на управление MinIO: общий дизайн

Краткое описание форм для заявителя и исполнителя. Подробности перевода в inventory,
ограничения и примеры — в [MINIO-REQUEST-CATALOG.md](MINIO-REQUEST-CATALOG.md).
Основание: текущие возможности роли `minio-configuration` 1.0.0.

## Общие принципы

- Четыре типа заявок: **Бакет**, **Учётная запись**, **Группа**, **Доступ**.
- Система заявок не связана с MinIO и не содержит справочников кластера.
  Имена вводятся текстом; существование объектов и текущие настройки проверяет исполнитель.
- Заявитель описывает желаемое изменение. Знать IAM, ARN, Sid и формат inventory не нужно.
- Inventory служит источником описания конфигурации, но может отличаться от кластера.
  Исполнитель сверяет сведения и уточняет неоднозначности до изменения.
- Создание пользователя, группы или бакета само по себе не выдаёт права на данные.
  Начальные права можно описать связанным разделом «Доступ» в той же заявке.
- **«Аноним (все без авторизации)» — встроенный пользователь на уровне заявок.**
  Его не создают, не удаляют, не блокируют и не включают в группы. Ему только меняют
  доступ к бакетам и их содержимому. Это специальный получатель, не имя учётной записи.
- Поля, не относящиеся к выбранной операции, не заполняются. Подойдут обычные текстовые
  шаблоны; динамические формы и интеграции не требуются.

## Общие поля

| Поле | Содержание |
| --- | --- |
| Кластер / окружение | Текстовое обозначение; известный endpoint — для уточнения |
| Операция | Один из вариантов выбранного типа заявки |
| Цель / причина | Краткий текст |
| Ответственный | Человек или команда приложения/ресурса; при создании обязателен |
| Желаемое время | Необязательно; для смены ключа — согласованное окно обновления приложения |
| Связанная заявка | Необязательно; например, первоначальное предоставление доступа |

Номер и инициатор — обычные реквизиты системы заявок. Секретные ключи в заявках не хранятся.

## 1. Бакет

| Поле | Варианты / содержание |
| --- | --- |
| Операция | Создать; изменить хранение версий; удалить |
| Имя бакета | Точное имя, текстом |
| Хранение версий | При создании: да / нет; при изменении: включить / приостановить |
| Подтверждение удаления | Для удаления: подтверждение ответственного на удаление бакета, содержимого и версий |
| Начальные доступы | Необязательно: строки по форме «Доступ» |

Новый бакет по умолчанию закрыт для «Анонима». Приостановка versioning не удаляет
накопленные версии. Квоты, lifecycle, переименование и перенос данных в эту форму
пока не входят: роль их не настраивает. Удаление имеет ограничения исполнения,
указанные в подробном каталоге; оно не ограничено только пустыми бакетами.

## 2. Учётная запись

Форма для обычных внутренних пользователей MinIO, исключая встроенного «Анонима».

| Поле | Варианты / содержание |
| --- | --- |
| Операция | Создать; заблокировать; разблокировать; заменить secret key; удалить |
| Имя пользователя | Точное имя / access key, текстом |
| Приложение | Какое приложение или процесс использует учётную запись |
| Получатель секрета | Для создания/замены: кому передать ключ защищённым способом; не сам ключ |
| Начальные доступы / группы | Необязательно: связанные разделы «Доступ» / «Группа» |

Блокировка сохраняет назначения, разблокировка возвращает возможность их использовать.
Замена secret key не создаёт второй параллельный ключ. Переименование, service accounts,
STS, root и LDAP/OIDC не входят в эту форму исполнения текущей ролью.

## 3. Группа

Группа может представлять понятную заявителю роль доступа, например «читатели отчётов».
Технически это группа MinIO.

| Поле | Варианты / содержание |
| --- | --- |
| Операция | Создать; добавить пользователей; исключить пользователей; заблокировать; разблокировать |
| Имя группы | Точное имя, текстом |
| Пользователи | При создании — хотя бы один участник; при изменении членства — список добавляемых или исключаемых имён |
| Назначение группы | Краткое описание при создании |
| Начальные права | Необязательно: строки по форме «Доступ» с получателем «группа» |

Права существующей группы меняются заявкой «Доступ». Членство даёт весь набор прав
группы; исполнитель описывает его в заявке после сверки. Блокировка группы не блокирует
самих пользователей и не снимает их прямые права или права других групп.
Физическое удаление группы текущая роль штатно не выполняет, поэтому такой операции
в исполняемом каталоге пока нет.

## 4. Доступ

Одна строка описывает одного получателя, одну область и требуемые операции.
Для разных областей добавить строки.

| Поле | Варианты / содержание |
| --- | --- |
| Операция | Предоставить; изменить; отозвать; для обычного пользователя/группы также установить или снять явный запрет |
| Тип получателя | Обычный пользователь; группа; встроенный «Аноним» |
| Имя получателя | Для пользователя/группы — текстом; для «Анонима» не требуется |
| Бакет | Точное имя; несколько имён или маска — расширенный вариант |
| Область содержимого | Весь бакет; префикс, например `reports/`; конкретный ключ, например `reports/result.csv` |
| Операции с содержимым | Читать; загружать/перезаписывать; удалять — выбираются независимо |
| Список объектов | Разрешить; не выдавать этим назначением; явно запретить в бакете |
| Дополнительные операции | История версий; удаление конкретных версий; теги — только при необходимости |
| Управление бакетами | Создавать в согласованной области имён; удалять выбранные бакеты; читать/менять versioning; общий список бакетов — отдельный запрос |
| Срок | Постоянно либо до даты; отзыв по дате сейчас требует отдельной задачи исполнителю |

Быстрые профили: «только список», «чтение по имени», «просмотр и чтение», «только
загрузка», «чтение и запись по имени», «чтение и запись без удаления», «чтение,
запись и удаление». Исполнитель раскрывает профиль в конкретные операции.

**Чтение/запись без списка допустимы.** «Не выдавать список» не отменяет права из
других назначений; «явно запретить» перекрывает разрешения обычного пользователя,
включая полученные через группы. Запись включает перезапись, удаление выбирается отдельно.

Для **«Анонима»** применяются операции с содержимым и выбор «разрешить / не разрешать
список» в итоговой политике бакета. Полный отзыв закрывает анонимный доступ к выбранному
бакету, частичный убирает выбранные разрешения. Явный общий запрет в bucket policy
не используется как обычное средство отзыва: он может затронуть других пользователей.
Права на администрирование бакетов «Анониму» стандартной формой не выдаются.

## Исполнение и результат

Исполнитель вручную сверяет заявку с inventory, при необходимости читает состояние
MinIO, готовит изменение и применяет роль. Каждая заявка изменяет только указанный
способ назначения:

- «Доступ» пользователю — его прямые права.
- «Доступ» группе — права самой группы для всех её участников.
- «Группа: исключить пользователя» — членство указанного пользователя в этой группе.
- «Доступ» встроенному «Анониму» — анонимные разрешения выбранного бакета.

Если запрошено удалить прямое право пользователя, а такого назначения нет,
заявка отклоняется с объяснением. Например: «Прямого права чтения нет; оно получено
через группу readers. Нужна заявка “Группа: исключить пользователя из readers”».
Исполнитель не заменяет операцию исключением из группы, изменением её прав или
добавлением запрета. Если право выдано и напрямую, и через группу, снимается только
прямое назначение; в результате отмечается, что групповое право сохраняется.
Не затронутые заявкой настройки сохраняются.

Результат в заявке: кому, на какие ресурсы и какие операции выданы/отозваны; что
изменено в inventory; когда применено и что фактически проверено. Различать изменение
описания и подтверждённое состояние кластера.

Удаление бакета/пользователя требует особой проверки: текущая роль использует
удаление всех отсутствующих в inventory ресурсов. Частичный inventory с флагом
удаления недопустим. Подробный порядок приведён в основном каталоге.

Матрица прав обсуждается отдельно и не входит в этот дизайн форм заявок.
